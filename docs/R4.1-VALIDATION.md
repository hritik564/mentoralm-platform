# R4.1 — Roadmap visual polish and navbar clearance

The R4 structure, six-stage content, page order, exact shared Menti artwork and responsive interaction model are preserved. `AGENTS.md` and relevant development/design/architecture/website documentation were read before editing. This refinement stops at Journey.

## 1. Files changed

- `src/styles/journey.css`
- `src/components/home/journey/JourneyExperience.tsx`
- `src/components/home/journey/JourneyLandscape.tsx`
- `src/components/home/journey/JourneyPath.tsx`
- `src/components/home/journey/JourneyStep.tsx`
- `tests/journey.spec.ts`
- `docs/DESIGN-SYSTEM.md`, this report and review evidence under `docs/reviews/r4.1/`

The [scope audit](reviews/r4.1/scope-verification.json) confirms 73 baseline source/test/asset/config files unchanged. This includes Navbar, Hero, Modules, shared Menti/gaze utilities, content records, page composition, every later section and dependencies. No Purpose reorder occurred.

## 2. Navbar/anchor clearance

Journey uses `scroll-margin-top: var(--header-height)` alongside the existing document scroll padding. Header tokens continue to adapt to desktop/mobile; no Navbar implementation changed.

Actual direct tablet navigation exposed the underlying timing issue: the initial browser fragment target used a taller pre-hydration layout, before the preceding Modules section switched to its responsive rail. CSS clearance alone did not correct that stale target. Journey now aligns its own fragment once after fonts and two paint frames, using native `scrollIntoView` and the CSS offsets. It applies only to initial `#journey` and hash navigation. Wheel, pointer or keyboard input cancels pending correction; listeners/frames are cleaned up. There is no continuous scroll listener, pinned scene or scroll hijacking.

Direct navigation and actual activation of the Hero's Journey link are tested at all six projects, with an additional 1440×900 direct-anchor check. The full eyebrow and heading must remain below the sticky rail and within the viewport. The [anchor screenshot](reviews/r4.1/direct-journey-anchor.png) records the actual destination with Navbar visible.

## 3. Roadmap visual changes

The existing composition gains a third mountain layer, clearer city silhouette, separated clouds and a brighter warm horizon. The 4px route and 24px low-opacity halo strengthen its visual hierarchy. The scene remains predominantly light and naturally scrollable; the approved reference is not embedded as a background.

## 4. Progressive colors

Desaturated grey-blue at 01 evolves through cyan, blue/violet, violet/magenta and magenta into gold at 06. High-opacity light card tints and matching markers/icons keep this one coherent environment. Navy titles and unchanged description colors maintain readability. No stage content or meaning changes.

## 5. Cumulative path

The existing active-stage precedence remains focus → hover → selected. Decorative segments ending at or before the active stage gain static cumulative emphasis; later segments remain quiet. Stage 4 illuminates 1→2→3→4, while Stage 6 illuminates the complete route. Reached nodes reinforce the progression. On mobile the existing vertical connector gains corresponding outgoing segment emphasis. These attributes express local visual emphasis, not saved progress.

## 6. Cards

Desktop minimum height decreases from 285px to 248px, with tighter padding/gaps and icons reduced from 52px to 44px. Titles, full approved descriptions and 13px body text remain. Tablet first-row cards retain a uniform 220px minimum and the SVG return route is adjusted to the resulting node centers. Mobile layout and comfortable full-card targets remain unchanged.

## 7. Menti gaze

The exact existing component and `mentiGazeToward` helper are reused. Journey aims toward the active card center, producing a clearer local reaction while retaining the 2.4px/1.8px bounds. No active stage resets pupils to neutral; pause/reduced motion removes tracking. A subtle stage-colored speech edge reinforces guidance. The wording remains “I’ll guide you step by step,” with the future-guide qualification unchanged. Hero and Module characters are unaffected.

## 8. Stage 1

A cooler grey-blue panel, quieter shadow and existing crossroads cue communicate uncertainty without an alarming or discouraging tone. Its starting node is emphasized when active, with later segments left quiet.

## 9. Stage 6 destination

The final panel has a warm sunrise tint, gold border, stronger node/glow and gold icon surface. The final active node retains its gold fill. Desktop uses a small destination flag above the node; tablet/mobile omit that flag to keep it clear of adjacent cards. The distant city, horizon light and separate scenic flag support arrival. The six-stage narrative and all text stay intact.

## 10. Responsive behavior

Six desktop columns, three-column tablet rows with a 03→04 return connection, and the vertical mobile journey are preserved. Reviewed sizes: 1920×1080, 1440×1000, 1440×900, 1024×768, 768×1024, 390×844 and 320×740. No Menti/card overlap, clipped text or document-level horizontal overflow was found. [Review observations](reviews/r4.1/review-observations.json) record all seven sizes. Short viewports scroll naturally to the rest of the section.

## 11. Accessibility

Semantic h2/h3 headings, the ordered list, description relationships, keyboard Tab/Enter/Space, `aria-pressed`, focus precedence and the 3px focus outline remain. No essential information depends on hover. Full-card touch targets and high-opacity light surfaces remain. Landscape, route and decorative details are hidden from assistive technology. Journey and whole-homepage axe WCAG 2.1 A/AA scans are covered by the suite.

## 12. Reduced motion

Float/blink, gaze, positional hover and transitions are disabled. Full content and static cumulative path emphasis remain. The independent pause control and no-JavaScript static rendering are preserved. No new route loop or continuous animation is introduced.

## 13. Performance

No dependency, raster asset, font, video, canvas, WebGL or animation library is added. The refinement uses scoped CSS, small SVG changes, existing bounded gaze and a cancellable two-frame fragment correction. There is no additional persistent animation loop or expensive visual filter. The homepage still prerenders statically. Field performance was not benchmarked.

## 14. Tests/checks actually executed

Final full-suite result: **169 passed, 5 viewport-conditional skips, 0 failures** using `PLAYWRIGHT_BROWSERS_PATH=/private/tmp/mentoralm-browsers npm test -- --workers=1` (174 cases, 2.4 minutes).

Typecheck, lint (zero warnings), format check and production build passed. Focused Journey suite: 42 passed. New tests cover real direct/link anchor clearance, cumulative active/quiet path segments and reached nodes, bounded gaze direction, reduced-motion cumulative colors, cool opening/gold destination and compact readable cards. Original order/content, keyboard, mobile geometry, no-JavaScript and axe tests remain.

A prior complete full run recorded 168 passes, 5 skips and one focus failure in the unchanged narrow-mobile Navbar test while independent screenshot review was running. That case then passed three isolated repeats, and the final complete serial run passed without concurrent review capture. No Navbar code or test was changed. The observed failure is recorded as intermittent; its underlying cause was not established.

An initial focused run passed 41 cases and failed the real tablet-landscape anchor test. This exposed the hydration target shift described above. After the Journey-only correction all 42 focused cases passed. An intermediate full run was stopped for the final tablet flag adjustment; it is not counted as a complete validation run.

[Pixel comparison](reviews/r4.1/regression-comparison.json) against R4 records zero differing pixels for Hero at 1440×886 and the complete Modules section at 1440×944. Scope hashes independently verify their source/artwork unchanged.
