# L3 — Academic engine implementation report

Status: complete locally on 2026-10-01. Scope is L3 only; no Admin/Instructor UI, intelligence engine, communications, deployment, push, DNS change or production database connection.

1. **Question Bank:** Reusable QuestionBank → Question → normalized QuestionOption. Supports SINGLE_CHOICE, MULTIPLE_CHOICE, TRUE_FALSE, SHORT_TEXT and LONG_TEXT. Ordered ActivityQuestion associations own scoring weight. Content renders as escaped plain text; executable HTML is never interpreted. Publication, ordering and points are constrained. Future privileged authoring must validate option configuration before publication.
2. **Quiz:** Constrained QUIZ AcademicActivity, instructions, optional pass threshold/attempt limit and post-submit review policy. Start resumes one existing open attempt; responses explicitly Save and reload/resume. Final Submit confirms intent, requires answers, scores on the server and freezes responses. Single/true-false award configured points for the correct selection; multiple choice uses exact sets with no partial credit. Concurrent submission is idempotent. Correct flags, explanations and awarded points never enter pre-submit payloads. SHORT/LONG_TEXT require review, not invented automatic grading.
3. **Assessment:** A distinct ASSESSMENT activity kind/completion source reuses normalized attempts and response snapshots. Objective scores and text-review state are supported. Each attempt snapshots prompts/options/keys/points and result policy at start, preserving historical integrity despite later author edits. Responses remain available to a future analysis boundary; no personality, career, DNA, roadmap or psychological interpretation is produced.
4. **Assignments:** Published ASSIGNMENT specialization with instructions, informational due date, allowed TEXT/FILE/TEXT_AND_FILE modes, file limits, acceptance and resubmission policy. Per-student submission retains immutable numbered versions, text/files, current version status and appended reviewer feedback. UUID request keys make retries idempotent; concurrent resubmissions get distinct stable numbers. UNDER_REVIEW/ACCEPTED block resubmission. Scoped staff review exists as a server/domain service without UI or student endpoint. PDF, raster images and UTF-8 text uploads use private generated keys; HTML, executables, SVG, macro files and DOCX are not accepted.
5. **Attendance:** BatchSession supports dates/status, optional Course/live-item association and controlled location/link metadata. Membership-linked AttendanceRecord supports PRESENT/ABSENT/LATE/EXCUSED. Assigned Instructor/Admin operations validate Batch/session/member/course scope and audit changes; students read only their applicable held sessions. Membership and batch dates apply. PRESENT/LATE count as attended, EXCUSED is excluded, UNRECORDED stays in the denominator. Historical records remain after membership departure, subject to current workspace/course access.
6. **Unified progress:** Typed item completion projections identify eligibility, source, completion and timestamp. Required published configured LESSON/QUIZ/ASSIGNMENT/ASSESSMENT contribute once. Optional/unconfigured items, RESOURCE and LIVE_SESSION do not silently enter the denominator. Lessons retain manual completion; quiz/assessment threshold requires a genuinely passing scored attempt, otherwise a valid submission; assignments require acceptance or valid submission according to policy. Section/Course progress and next learning item use this one boundary. The L2 `lessonProgress` export is a compatibility alias to the same aggregator.
7. **Course completion:** Explicit `academicCompletionEnabled` opt-in prevents changing existing L2 Course policy. All meaningful required contributors and any configured attendance threshold must be satisfied; empty courses never complete. Serializable server evaluation updates Enrollment COMPLETED and preserves its first completedAt. Curriculum/condition changes can reopen IN_PROGRESS without changing that first timestamp. Reads immediately project current eligibility; future publication/policy changes invoke scoped audited reconciliation to synchronize the materialized Enrollment row. Thresholds use unrounded facts, not display rounding.
8. **Certificates:** Separate Course `certificateEnabled` policy. Unique student/Course Certificate record, unpredictable random code, issued date and ACTIVE/SUSPENDED/REVOKED status. Concurrent evaluation creates at most one record. Eligibility loss suspends; requalification may restore suspension; manual Admin revocation stays revoked. Students have no issuance or status setter. Own-record display is real; optional attached private PDF supports authorized preview/download. No certificate PDF is invented, no designer/public verification added.
9. **Dashboard:** Reads LMS course progress, final eligibility/completion, typed next-item destination and real certificate availability. It never scores, completes, issues or owns LMS state. Actual attached certificate documents appear through a controlled Dashboard Resources adapter without duplicated storage; record-only certificates remain displayable inside LMS. Existing Dashboard/public Student ID and Batch visibility rules remain intact.
10. **Security:** Current verified student, PostgreSQL entitlement, Enrollment, published Course/Section/item/subtype and exact ownership protect every academic operation. Draft/unrelated/guessed IDs, another student's attempts/submissions/files/attendance/certificates, revoked access, owner/score/progress/reviewer/status injection and self-issuance are denied. Strict typed field allowlists, same-origin requests, bounded JSON/multipart bodies, MIME/signature validation, containment, no-follow/exclusive files, cleanup and safe response headers protect storage. Database triggers protect submitted answer/option and historical version content; subtype, date, size, open-attempt and uniqueness constraints protect invariants. Persisted roles and assigned scope protect audited staff services; there are no privileged HTTP controls.
